# Changelog

## 0.2.0 (2026-11-08)

### Breaking changes

- Regenerate your type stubs with `sgalchemy stubs` after you upgrade. Stubs generated by 0.1.0
  fail `sgalchemy stubs --check`, and in the new stubs assigning to a non-editable field is a type
  error, as it already fails at run time.

### Added

- `sgalchemy stubs --site` and `sgalchemy schema refresh` sign in with `SGALCHEMY_SESSION_TOKEN`
  when you omit `--script-name`.
- `Session.add()` and `AsyncSession.add()` accept an entity from a closed session and commit later
  edits to it; editing such an entity before you add it raises an error instead of losing the edit.
- `create_async_engine()` uses the threaded strategy when you pass `sync_connection=`, `creator=`,
  or `max_workers=`, so `strategy='threaded'` is no longer needed.
- `order_by()` accepts a bare field, such as `order_by(Shot.code)`, to sort ascending.
- `sgalchemy` exports the types its public signatures use, such as `Filter`, `Ordering`, and
  `JoinedLoad`, so you can annotate your own code with them.

### Changed

- `sgalchemy stubs` first prints a `schema:` line saying where the schema came from and, for a
  cached copy, when it was fetched.
- Passing an async engine or client where a sync one is expected, or the reverse, raises
  `TypeError` naming the right call.
- Error messages suggest the closest name for a misspelled field and name the extras to install
  when no SG provider is installed.

### Fixed

- Query methods such as `where()`, `options()`, and `order_by()` raise `TypeError` for arguments
  they cannot use instead of silently ignoring them, including conditions combined with Python's
  `and`, `or`, `not`, or `in`. Use `and_()`, `or_()`, or `in_()`.
- `in_()` and `not_in()` given a list or other iterable filter by its items instead of sending it
  as one nested value.
- Interrupting `commit()` after SG saved a batch, for example with Ctrl-C, no longer leaves that
  work staged for the next `commit()` to send again.
- `sgalchemy.testing.engine_over()` no longer writes the fake site's schema into your real schema
  cache.
- Type checkers accept `shotgun_api3` and sg-python-api clients as `ShotgunLike` and
  `AsyncShotgunLike`.
